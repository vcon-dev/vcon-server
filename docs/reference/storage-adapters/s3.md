# S3 storage adapter

Stores each vCon as a JSON object in Amazon S3 or an S3-compatible service, under a date prefix, with a small pointer object for lookups by UUID.

Module: `storage.s3`. Needs `boto3`, from the `storage` dependency group.

## Configure the adapter

Amazon S3:

```yaml
storages:
  s3:
    module: storage.s3
    options:
      aws_access_key_id: example-key
      aws_secret_access_key: example-secret
      aws_bucket: vcon-archive
      aws_region: us-west-2
      s3_path: vcons/production
```

MinIO or another S3-compatible service:

```yaml
storages:
  minio:
    module: storage.s3
    options:
      aws_access_key_id: minioadmin
      aws_secret_access_key: minioadmin
      aws_bucket: vcons
      endpoint_url: http://minio:9000
```

## Set the options

`default_options` is empty, so a storage entry with no `options` block fails on every write.

| Option | Type | Default | Description |
|---|---|---|---|
| `aws_access_key_id` | string | none | Access key. Required |
| `aws_secret_access_key` | string | none | Secret key. Required |
| `aws_bucket` | string | none | Bucket name. Required |
| `aws_region` | string | none | Region. Passed to the client only when set |
| `endpoint_url` | string | none | Custom endpoint for S3-compatible services |
| `s3_path` | string | none | Key prefix. A trailing slash is removed |

## Check the object layout

`save` writes two objects:

| Object | Key | Content |
|---|---|---|
| vCon | `[s3_path/]YYYY/MM/DD/<uuid>.vcon` | The vCon as JSON. The date comes from `created_at` |
| Lookup pointer | `[s3_path/]lookup/<uuid>.txt` | The `YYYY/MM/DD` string |

## Save a vCon

`save` reads the vCon through `VconRedis`, applies `EGRESS_FORMAT_VERSION`, puts the vCon object, then puts the pointer.

## Read a vCon

`get` reads the pointer to find the date, then reads the vCon object. It returns `None` on any error, including a missing pointer. An object with no pointer cannot be read through this adapter.

## Delete a vCon

`delete` reads the pointer, then deletes the vCon object and the pointer. It returns `True` on success. It returns `False` on any error, including a missing pointer, and does not raise.

## Handle a failed write

Any exception raises, so the server moves the vCon to the [storage DLQ](index.md#handle-a-failed-write). A vCon with no `created_at` fails here, because the date prefix cannot be built. The adapter sets no retry of its own.

A repeated `save` overwrites both objects with the same keys. If the first put succeeds and the pointer put fails, the replay repairs the pointer.
