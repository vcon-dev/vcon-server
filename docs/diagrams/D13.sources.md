## Test note

Steps 11, 15 and 16 depend on FastAPI ordering, not on repo code. A small app with the same dependency shape on the pinned FastAPI 0.115.6 gave these results:

| Request | Status |
|---|---|
| `api_router` route, wrong key, valid JSON that fails the body model | 403 |
| `api_router` route, wrong key, malformed JSON | 422 |
| External ingress, no key, body fails the model | 422 |
| External ingress, no `ingress_list`, no key | 422 |
| External ingress, no key, valid input | 403 |
| `/docs`, `/redoc`, `/openapi.json`, no key | 200 |

The test used a stand-in app, not `api/api.py` itself.

## Left out of the drawing

- `/docs`, `/redoc` and `/openapi.json` are public through FastAPI defaults, because `api/api.py:85` does not turn them off.
- `CORSMiddleware` allows all origins (`api/api.py:204-206`). It checks no key.
- `VersionHeaderMiddleware` adds version headers (`api/api.py:210-228`). It checks no key.
