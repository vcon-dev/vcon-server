# D07 traces the vCon lifecycle

Diagram: `D07-vcon-lifecycle.mmd`. Line numbers refer to the worktree at the time of drawing.

The states combine two facts: where the id sits in a queue, and where the body sits. Wrapping up pushes egress and saves to storage in the same pass, so one vCon can take the egress edge and a storage edge together.

## Notes cover timing and carried data

- Default TTLs: `VCON_REDIS_EXPIRY` 3600 s (`common/settings.py:38`), `VCON_DLQ_EXPIRY` 604800 s (`common/settings.py:56`), `expire_vcon` 86400 s.
- Setting `VCON_DLQ_EXPIRY` to 0 leaves the TTL alone on both DLQ paths (`conserver/main.py:762`, `common/lib/queue.py:126`).
- The TTL keeps running while the id waits. If it lapses, the id stays on its list and links get `None` from `get_vcon` unless a storage copy exists (`common/lib/vcon_redis.py:178`). The `tag` link then halts (`conserver/links/tag/__init__.py:19`).
- An id on a backend DLQ can outlive its body in the same way. The replay save then fails and the id stays put (`api/api.py:1234`).
- `VconRedis` writes pass through `_enforce_spec_on_write` (`common/lib/vcon_redis.py:61`). The API intake path (`api/api.py:789`) and the follower (`conserver/follower.py:49`) write without it. Reads normalise legacy fields (`common/lib/vcon_redis.py:223`).
- `VCON_STORAGE_FALLBACK_ENABLED` gates the `VconRedis` read path only (`common/lib/vcon_redis.py:120`). The API path at `api/api.py:491` does not check it.
- Any `lawful_basis` attachment travels with the body through every state. No state creates or checks one.
