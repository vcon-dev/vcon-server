## Notes state the contract for link authors

- Signature: `run(vcon_uuid, link_name, opts)`. The server always passes the third argument (`conserver/main.py:603`), and it is `None` when the config has no `options` key (`conserver/main.py:574`). A link's `default_options` default does not apply in that case.
- Return the id to continue, a different id to swap the vCon, or a falsy value to halt.
- `status` is `"success"` for a halt too. Only the `conserver.link.count` metric separates them, with `outcome` of `halt` (`conserver/main.py:626`).
- If `after_link` raises on the success path, the `except` at `conserver/main.py:646` treats it as a link failure: a second `after_link` call with `"error"`, then the DLQ.
- A tracer error only stops the chain when its options set `dlq_vcon_on_error` (`conserver/main.py:545`). A failing tracer with no `options` key also stops the chain and sends the vCon to the DLQ, so always set `options`, even as `options: {}`.
- An unknown link name or failed import raises before the `try` at `conserver/main.py:599`, so `after_link` does not run and the vCon reaches the DLQ.
- `after_link` config comes from `options.after_link` (`conserver/main.py:598`).
- `hook.py` and `after_link_hook.py` ship as no-ops and are meant to be replaced at image build time (`conserver/hook.py:4`, `conserver/after_link_hook.py:4`).
- `after_processing` also runs after a skip (`conserver/main.py:764`) and gets the current id (`conserver/main.py:767`). An exception from it is not caught.
