## Limits apply to this drawing

- The ingress path calls plain EXPIRE, so it can shorten a longer TTL or put a TTL on a persistent body. The storage path does neither (`common/lib/queue.py:126`).
- `enqueue_dlq` does not check that the body exists. An id can sit on the ingress DLQ after its body has expired.
- A worker holds a popped id only in memory. No in-flight list exists, so a killed worker loses that id. This is not drawn because no code handles it.
- A saved vCon and a storage DLQ entry can exist together when one backend succeeds and another fails.
- The `POST /dlq/reprocess` move is two Redis commands, not one atomic step (`api/api.py:1168-1171`).
